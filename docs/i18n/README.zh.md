# 双语文档

[English](README.md) | 中文

Lemma 的文档以英文与简体中文两种语言维护。本页定义配对契约、它的检查及适用范围；[terminology.md](terminology.md) 是术语的权威来源。

## 配对契约

- **两种语言具有同等效力。** 文档可以先用任一语言写成，再据此翻译出对应版本。两个文件表述相同的内容。
- **一对文件是三个同级文件。** 英文 `foo.md`、中文 `foo.zh.md` 与一致性记录 `foo.i18n.yaml` 位于同一目录。修改其中一侧的提交同时更新另一侧与记录。
- **一致性记录。** `foo.i18n.yaml` 为每个标题小节保存一个条目。键是该小节英文标题的 slug 路径（第一个标题之前的文字为 `/`；重复的路径加 `~2`、`~3`……），条目保存该小节英文文本与中文文本各自的哈希，代码块计算在内：

  ```yaml
  /bilingual-documentation/the-pairing-contract:
    en: 0b5c1e0e3f1a2d47
    zh: 9a4e8c2f71d03b65
  ```

  一侧的第 `i` 个小节对应另一侧的第 `i` 个小节。修改不同的小节改动的是记录中不同的行，因此只有两个分支修改了同一小节时，合并才会在记录上冲突；先解决 Markdown 的冲突，再重新记录这对文件。记录一对文件，即声明两侧在当前内容下表述相同。
- **语言切换行。** H1 的下一行在英文文件中为 `English | [中文](foo.zh.md)`，在中文文件中为 `[English](foo.md) | 中文`。
- **结构与对应文件一致。** 标题层级与顺序、列表类型与条目数、表格行列数以及链接目标一一对应。代码块逐行对应，只有注释可以翻译。中文文件中指向已配对文档的链接指向其 `.zh.md` 一侧。

## 检查

`just docs-pairing` 检查每一对文件：

1. 范围内的每份文档都有对应文件与记录。
2. 两侧的标题层级与顺序相同。
3. 记录等于由当前内容计算出的记录，因此任一侧改动后未重新记录即失败。
4. 例外文档没有 `.zh.md`，也没有 `.i18n.yaml`。

`just docs-pairing <file>...` 只检查指定的配对；一对文件中的任一文件都可以指代这一对。Spec CI 运行完整检查。

检查只比较哈希与标题结构。已记录的一对文件仍可能在含义、术语、列表、表格或链接上不一致；记录之前先确认这些内容。

## 更新一对文件

1. 运行 `just docs-brief`，或用 `just docs-brief <file>...` 指定配对。它为每对不同步的文件打印一份翻译简报。若只有一侧修改了部分小节，简报包含每个改动小节最近一次与记录相符的已提交原文、当前原文、带行号的当前对应文本，以及改动涉及的[术语](terminology.md)行。新配对、未记录的配对、两侧都有改动，或增删了小节时，简报改为整篇文档的任务。
2. 修改对应文件。只改原文改动涉及的内容，其余部分保留已审阅的措辞。
3. 用 `just docs-pairing --write <file>` 记录这对文件，再用 `just docs-pairing <file>` 检查。`--write --all` 一次记录全部配对。

## 范围与例外

**范围**：所有维护中的 Markdown 文档，包括 `README.md` 与 `AGENTS.md` 文件。

**例外**（不配对；检查会拒绝它们的 `.zh.md` 或 `.i18n.yaml`）：

- `SKILL.md` 文件及各 skill 下的参考资料，它们只有英文，因为工具会原样读取。
- 生成文件。
- [terminology.md](terminology.md)，它本身就是双语的。
