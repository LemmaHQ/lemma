# 防御性模式

[English](README.md) | 中文

来之不易的规则：本目录中的每一条模式都是本仓库在评审中强制执行的要求，以规则本身及其防止的缺陷来陈述。每条规则都写明必须成立的条件、评审者据以判断的标准、规则的边界与例外的批准人，以及一个正确示例和一个错误示例。在修改某类产物之前，先阅读对应的页面。

## 为什么有这些规则

下面的内容大多出自五个习惯，每一页都是它们在某一类产物上的应用：

- **让正确性显式化。** 把它写进结构里——具名的调用点、显式的生命周期、显式的条件与类型——而不是事后靠时序来弥补。
- **保持单一事实来源。** 一份数据只有一条读取路径，一条事实只有一个归属，共享状态只有一个所有者。
- **通过已注册的扩展点扩展。** 新 provider 走适配器分发，新工具走工具注册表；已有的承载者不再接收新逻辑，而不是在内部不断增加分支。
- **让改动面等于评审面。** 一次改动只包含其声明的行为变化所需的行，迁移是移动代码而不是重写代码，对性能敏感的改动附带测量数据。
- **要求证据。** 每个论断都可证伪、可重新计算——有改动前后的测量，或由测试或命令检查——而不是靠人工保持同步。
